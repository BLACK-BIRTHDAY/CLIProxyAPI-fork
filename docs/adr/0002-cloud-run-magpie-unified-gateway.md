# Unify MAGPIE Backend into Cloud Run Gateway via Sidecar Process and Plugin Resource UI

Status: accepted

To serve both CLIProxyAPI OAuth/API providers and MAGPIE Google AI Studio accounts from a single Google Cloud Run endpoint (`0.0.0.0:$PORT`) and management console without maintaining a forked `management.html` bundle or suffering credential-wide cooldowns from a single static `api-keys.gemini` entry:

1. **Pre-installed Sidecar & GCS FUSE Split Storage**: Pre-install and SHA-256-verify the pinned Linux `aistudio2api` (`v0.2.19-magpie.1`) binary at `/app/magpie/aistudio2api` (`MAGPIE_PREINSTALLED_BIN`) inside the container image so GCS FUSE `noexec` mounts never block execution, persist durable state (`config.yaml`, `auths/`, and `magpie/{config.json,.env,auth/}`) on the mounted GCS bucket (`/root/.antigravity_tools` or `/data`), and isolate `bbolt` (`kv.db`) plus `aistudio2api` runtime logs/PID files under `/tmp/` to avoid FUSE `mmap` failures and write-rate throttling.
2. **Namespace & Protocol Passthrough**: Advertise filtered `gemini-*` MAGPIE models on `/v1/models` and `/v1beta/models` with `owned_by: "magpie"` and the `(MAGPIE)/` prefix for both Client Model ID and Display Name so downstream clients group MAGPIE models separately while retaining `/` Gemini capability detection; forward matching `/v1beta/models/*` and `/v1/chat/completions` requests to the local `aistudio2api` daemon with deterministic 63-character SHA-256 bidirectional tool-name aliasing (`<54-char prefix>_<8-char sha256>`), tool root schema normalization, up to 2 silent temperature-perturbed retries on Malformed Empty Upstream Replies, and token accounting into CLIProxyAPI's usage statistics.
3. **Zero-Fork Unified Management UI**: Expose MAGPIE Quota (headless Account State Bundle import/export, account toggle/delete, and active cooldown windows) and MAGPIE Settings (two-way `.env` and `/api/config` sync) through CLIProxyAPI's native plugin-resource menu contract (`/v0/resource/plugins/magpie/*` + `/v8/management/magpie/*`), preserving upstream `management.html` compatibility while sharing a single login session (`WEB_PASSWORD` / `MANAGEMENT_PASSWORD` / `API_KEY`).
