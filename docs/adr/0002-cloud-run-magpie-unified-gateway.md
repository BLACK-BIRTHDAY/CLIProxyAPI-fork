# Unify Google AI Studio into Cloud Run Gateway via Native cpa-plugin-aistudio2api and Direct /root/.cli-proxy-api Mount

Status: accepted

To serve both CLIProxyAPI OAuth/API providers and pooled Google AI Studio accounts from a single Google Cloud Run endpoint (`0.0.0.0:$PORT`) and management console without running custom sidecar processes, maintaining a forked `management.html` bundle, or requiring path symlinks:

1. **Native C ABI Plugin (`cpa-plugin-aistudio2api`)**: Load `jianli9158/cpa-plugin-aistudio2api` (`v1.1.8`, C ABI v1 / Schema v10) dynamically via CLIProxyAPI's standard Go plugin loader (`plugins.enabled: true`, `plugins.dir: "/root/.cli-proxy-api/plugins"`, `CGO_ENABLED=1`). This eliminates the internal sidecar process (`internal/magpie`), custom proxy forwarders, and internal process monitors while providing native upstream-compatible request handling, session rotation, and model discovery.
2. **Direct `/root/.cli-proxy-api` Storage Root & FUSE Resilience**: Mount the Cloud Run GCS bucket directly at `/root/.cli-proxy-api` (both CLIProxyAPI's standard auth root and the plugin's default data root). This unifies `config.yaml`, `antigravity-*.json` credentials, and `aistudio2api/accounts/<email>/` under a single clean directory structure, enabling native `sync_auth_files: true` without symlinks or legacy `/root/.antigravity_tools` paths. Cloud Run FUSE `mmap` limitations are addressed by automatically falling back `bbolt` (`cpa-kv.db`) to `/tmp/cpa-kv.db`.
3. **Upstream Management UI Compatibility**: Use the standard pre-downloaded upstream `management.html` (`ENV MANAGEMENT_STATIC_PATH=/app/static`) with zero custom UI forks. Authentication unifies under `ResolveEnvManagementSecret()` (`MANAGEMENT_PASSWORD` -> `WEB_PASSWORD` -> Cloud Run `API_KEY` -> `CPA_API_KEY`) and missing-key probing protection.
